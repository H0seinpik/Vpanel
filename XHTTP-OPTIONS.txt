==========================================================================
 تنظیمات XHTTP در پنل — چه چیزی اضافه شد و کدام را نباید زد
==========================================================================

تاریخ: 2026-09-29

همهٔ اینها از **خودِ Xray نصب شده روی این سرور** پرسیده شد
(یک تست برای هر گزینه)، نه از حدس یا اینترنت.

--------------------------------------------------------------------------
۱) Xray این گزینه‌ها را برای xhttp قبول می‌کند
--------------------------------------------------------------------------

  path              مسیر
  host              هاست
  mode              auto | packet-up | stream-up | stream-one
  extra.xmux        چند درخواست روی یک اتصال
  extra.xPaddingBytes
  extra.scMaxBufferedPosts / scMaxEachPostBytes / scMinPostsIntervalMs
  extra.noSSEHeader
  noGRPCHeader

  ⛔ headers نمیتواند کلید "host" داشته باشد — Xray رد میکند.

--------------------------------------------------------------------------
۲) هشدار مهم — دو گزینه که کلاینت را قطع میکنند
--------------------------------------------------------------------------

تست واقعی (سرور موقت + کلاینت واقعی):

  سرور stream-up    ← کلاینت بدون mode   ⇒  وصل نمیشود   ⛔
  سرور stream-one   ← کلاینت بدون mode   ⇒  وصل نمیشود   ⛔
  سرور packet-up    ← کلاینت بدون mode   ⇒  کار میکند    ✅
  سرور auto         ← کلاینت بدون mode   ⇒  کار میکند    ✅

چرا مهم است؟ چون **لینکی که به مشتری میدهی نمیتواند mode را همراه داشته
باشد**. پس اگر سرور را روی stream-up بگذاری، هر کلاینتی که لینک را import
کند قطع میشود — بیآنکه بدانی چرا.

برای همین پنل فقط این دو را ارائه میدهد:
    auto  (پیشفرض — امن)
    packet-up

--------------------------------------------------------------------------
۳) گزینه‌هایی که به پنل اضافه شد
--------------------------------------------------------------------------

در ویزارد، وقتی ترانسپورت را **xhttp** انتخاب کنی:

  • XHTTP mode
      auto          پیشفرض — با همهٔ کلاینتها کار میکند
      packet-up     آپلود سریعتر — باز هم با همهٔ کلاینتها کار میکند

  • XHTTP multiplexing (xmux)
      خاموش / روشن
      بیشینهٔ اتصال همزمان (پیشفرض ۸)
      بیشینهٔ عمر هر اتصال (پیشفرض ۱۵۰۰۰ میلیثانیه)

      این همان چیزی است که **تعداد درخواستها و فشار روی سرور را کم میکند**:
      چند درخواست روی یک اتصال میروند بهجای چند اتصال جداگانه.
      فقط سمت سرور است و کلاینت هیچ تنظیمی لازم ندارد.

  • XHTTP padding
      اختیاری (مثل 100-1000). اندازهٔ بستهها را میپوشاند،
      ولی ترافیک را کمی بیشتر میکند. برای کاهش فشار خالی بگذار.

--------------------------------------------------------------------------
۴) همین الان در سرور چه اعمال شده
--------------------------------------------------------------------------

  پورت 443  : mode=auto                       (تست شد: 200 OK)
  پورت 8443 : mode=packet-up + xmux(8, 15s)   (تست شد: 200 OK)

تست با کلاینت واقعی Xray و از طریق **همان لینکی که پنل میدهد** انجام شد —
لینکی که هیچکدام از این گزینهها را همراه ندارد، و باز هم وصل شد.
این دقیقاً همان چیزی است که باید درست باشد.

--------------------------------------------------------------------------
۵) پیشنهاد
--------------------------------------------------------------------------

  اگر هدفت کم شدن فشار روی سرور است:
      روی کانفیگ xhttp → xmux را روشن کن → ذخیره

  اگر هدفت سرعت آپلود است:
      mode را روی packet-up بگذار

  هیچوقت دنبال stream-up / stream-one نرو (در پنل هم نیست).

  یادآوری: مشکل اصلی کندیِ این سرور **رم** است (حدود ۲۳۰ مگابایت آزاد از
  ۴ گیگ). xmux کمک میکند ولی جای آزاد کردن رم را نمیگیرد.
