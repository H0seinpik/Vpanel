## "Severe speed drop" — the server is FAST; the bottleneck is client↔server

- Measured on the server: raw download **25.9 MB/s**; **through the node 26.8 MB/s**
  (faster than direct 23.7 MB/s); **CPU 8 %** on 2 cores; xray only 25 MB. So the
  node and the server network are NOT the bottleneck.
- Free RAM 243 MB (tight) but xray is tiny; only 2 external proxy connections open.
- Conclusion: the drop is on the path between the clients and the server (ISP /
  international link / **DPI throttling**) or the client's network. Same root cause as
  the "connect but no data" report — plain Shadowsocks is trivial for ISP DPI to
  fingerprint, and it then throttles or drops it. Recommended: **VLESS + REALITY**;
  test from another network/ISP; check route/time-of-day; fix the RAM as a secondary
  measure.
