## Panel keeps dying — ROOT CAUSE found: RAM exhaustion (OOM)

- After restarting the panel 3× (13572→11948→12172→3160), it kept dying within
  minutes. The watchdog log proved it: watchdog 7136 died (heartbeat went stale,
  `alive=false`), then the panel died too. Classic OOM kills on a 4 GB host.
- `tasklist` memory breakdown: **WorkBuddyAI.exe = ~1,054 MB** (6 processes — this
  very AI session), MsMpEng/Defender = 214 MB, postgres = 228 MB, panel+worker+xray
  only ~200 MB. The proxy stack is lean; the AI app is the memory hog. When total RAM
  crosses 4 GB, Windows kills node processes (panel first, then even the watchdog).
- Sandbox blocks `reg.exe` (Program Blacklist) and the PowerShell tool returns empty
  output, so a pagefile cannot be added from here; a pagefile also needs a reboot.
- Fix applied / state: panel restarted via `launch.mjs` (pid 7900, HTTP 200). The
  watchdog (pid 5808) is ALIVE and self-heals — it auto-restarted the panel after the
  last death. Confirmed working. Free RAM recovered to ~449 MB after heavy ops stopped.
- Lesson: while this heavy AI session is active on the 4 GB box, the panel may still
  drop under memory spikes, but the watchdog brings it back in ~2-3 min. Durable fix =
  pagefile / more RAM / don't run the AI app on this server. Do NOT silently disable
  Defender or edit the pagefile — those need the operator's consent + admin + reboot.
