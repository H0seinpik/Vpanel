## Subscription feed with `Subscription-Userinfo` (NEW endpoint)

- **There was no client-facing subscription endpoint.** `subscriptions/[id]` is
  admin-only (PATCH/DELETE behind `withAuth`), and the only `text/plain` route is a
  single-config download. A subscription URL is fetched by the phone with no cookies,
  so it cannot live behind `withAuth`.
- Added `src/app/api/sub/[token]/route.ts` — public, token = **subscription id**.
  - Body: the user's ACTIVE assignments' stored `shareLink`s (ACTIVE configs, scoped to
    the subscription's `serverId` when set), newline-joined, Base64 — the links are the
    same ones the panel delivers, unchanged.
  - Header: `Subscription-Userinfo: upload=…; download=…; total=…; expire=…`
    - `upload`/`download`: `trafficUsage` aggregate since `startsAt`, **scaled to the
      authoritative `subscription.trafficUsedBytes`** so a manual reset cannot
      over-report.
    - `total` = `subscription.trafficLimitBytes` (0 = unlimited).
    - `expire` = Unix seconds; `0` = never.
  - Also `Profile-Title` (username), `Content-Disposition`, `Cache-Control: no-store`,
    and `dynamic='force-dynamic'` / `revalidate=0` (MEMORY rule 10 — it reads the DB).
  - 404 unknown token / no active configs; 403 inactive or expired.
- Verified live with a TEMPORARY subscription (created and deleted inside
  `.vpanel/verify-subscription.ts`): **HTTP 200**,
  `upload=90526495; download=1144041395; total=10737418240; expire=1795623358`,
  16 links decoded from the Base64 body.
- `tsc` clean; `next build` succeeded; panel restarted (pid 11376).
